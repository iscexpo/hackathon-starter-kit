# Submission Instructions

Organizers must publish the official deadline, time zone, submission channel, eligibility terms, and demo requirements before accepting submissions. This guide describes the recommended process; event-specific rules take precedence when published clearly in advance.

## What to submit

Each team should provide:

1. **Project repository URL** that judges can access.
2. **Project description**: problem, intended users, solution, and what's working.
3. **Runnable setup instructions** with prerequisites and commands.
4. **Demo link** or live-demo details, as required by the event.
5. **Team information** in the format the event asks for.
6. **Technologies and data sources**, including relevant license and attribution details.
7. **AI-tool disclosure**, following the event policy.
8. **Known limitations and next steps**.

Start with [`SUBMISSION.md`](../SUBMISSION.md) in the project repo. Keep sensitive details and private contact information out of public documentation unless the event specifically requires disclosure through a private channel.

## Submission workflow

1. Read the event configuration and rules.
2. Complete `SUBMISSION.md`.
3. Make sure the repository and permitted demo links are accessible to judges.
4. Run the project from a clean setup where feasible; do not rely on undeclared local files or private environment variables.
5. Remove credentials, private data, and unrelated files from the repository history and current tree.
6. Submit using the official event channel before the deadline.
7. Save the confirmation or submission ID if the portal provides one.

## GitHub issue form option for organizers

If using the included [submission issue form](../.github/ISSUE_TEMPLATE/submission.yml), publish the repository's issue URL as the official channel and explain whether submissions will be public. Do not use public issues to collect private personal information. Organizers may disable issue submissions if the event requires a private portal.

## Final self-check

- [ ] Project name and summary are clear.
- [ ] Repository access has been tested in a logged-out or separate reviewer context.
- [ ] Main feature can be shown in the available demo format.
- [ ] Setup and test steps include exact commands.
- [ ] Dependencies, API services, and external datasets are documented.
- [ ] Known bugs and unfinished features are disclosed.
- [ ] Third-party attribution and license details are present.
- [ ] AI use is disclosed according to event rules.
- [ ] No credentials, unauthorized personal data, or confidential information are included.
- [ ] Submission has been sent through the official channel on time.
