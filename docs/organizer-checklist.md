# Organizer Launch Checklist

Use this checklist alongside `EVENT_CONFIG.md`. Assign an owner and completion date for each item in your event planning system.

## Governance and communication

- [ ] Publish the event name, purpose, hosts, official page, schedule, time zone, eligibility, team size, tracks, and deadline.
- [ ] Publish rules, code of conduct, reporting contacts, privacy practices, IP/license terms, and prize conditions.
- [ ] Explain what happens when a submission is late or a link does not work.
- [ ] Provide an accessible channel for questions and accommodation requests.

## Participant experience

- [ ] Test registration and submission as a participant.
- [ ] Test the project templates from a clean environment.
- [ ] Publish the required submission fields and examples.
- [ ] State which services need accounts, API keys, payment, or network access.
- [ ] Provide a plan for team formation, mentoring, and technical support where applicable.

## Judging

- [ ] Recruit judges and collect conflict-of-interest declarations.
- [ ] Publish criteria, point values, scale, tie-break rules, and any category awards before work begins.
- [ ] Calibrate judges and agree on evidence-based notes.
- [ ] Decide score handling, appeals, ties, and result-announcement procedures.
- [ ] Avoid judging using information not disclosed to teams in advance.

## Technical operations

- [ ] Verify repository and issue permissions.
- [ ] Decide whether submissions should be public, private, or accessible through a separate portal.
- [ ] Ensure no public form requests sensitive personal data.
- [ ] Prepare demo fallback guidance and a process for handling service outages.
- [ ] Run `python scripts/validate.py` and all template tests.
- [ ] Confirm license notices and third-party asset attribution.

## After the event

- [ ] Publish results through the announced channel.
- [ ] Share feedback only in the manner promised to participants.
- [ ] Handle prize follow-up and personal data under the published terms.
- [ ] Collect improvement feedback and update the kit through a reviewed pull request.
